# خادم درسي — قاعدة البيانات

تنفيذ المرحلة الأولى من `docs/darsy/06-phase5-technical-architecture.md`: المخطط والهجرات.

## التشغيل

```bash
pg_ctlcluster 16 main start     # تشغيل PostgreSQL
./db.sh                         # إنشاء قاعدة darsy وتطبيق كل الهجرات
./test.sh                       # إعادة البناء ثم محاولة كسر كل قاعدة
```

`db.sh` **يحذف القاعدة ويعيد بناءها** — للتطوير وحده. الإنتاج يستعمل هجرات تراكمية
عبر `node-pg-migrate` كما في مستند البنية التقنية.

## لماذا SQL يدوي لا ORM

قيمة هذا المخطط في **القيود والمشغّلات والفهارس الجزئية**، وهي ما تُسقطه معظم أدوات
الـORM حين تولّد المخطط بنفسها. الهجرات تُكتب هنا يدويًا، وأي ORM يُستعمل لاحقًا
يكون **للاستعلام فقط**.

## ما تفرضه قاعدة البيانات — وما يبقى على التطبيق

| القاعدة | كيف تُفرَض |
|---|---|
| العمولة + نصيب المدرس = السعر | `check` على الحجز وعلى الحركة |
| لا حجزان فرديان مؤكدان لنفس المدرس والموعد | فهرس فريد جزئي |
| لا رصيد سالب | مشغّل فوري بقفل صف |
| لا حركتان ماليتان لحجز واحد | `unique(booking_id)` |
| لا تعديل لقيمة حركة مسجّلة | مشغّل يمنع تغيير `gross_amount` |
| لا Webhook يُعالَج مرتين | `unique(provider, event_id)` |
| تقييم واحد لحجز **مكتمل** | `unique` + مشغّل يقرأ حالة الحجز |
| الحجز لمتعلّم تحت حسابك وحده | مشغّل يقرأ `children` |
| إيقاف فعّال واحد لكل مدرس | فهرس فريد جزئي |
| صيغة رقم الهاتف · حدود السعر · مقاعد الجماعية | `check` |
| اختيار شريحة العمولة · آلة حالات الحجز · صلاحية الدور | **التطبيق** |

## درسان من كتابة الاختبارات

**١. `or` في قيد `check` فخّ.** الصيغة البديهية

```sql
check ((kind = 'group' and group_seats between 2 and 12)
    or (kind = 'individual' and group_seats is null))
```

تمرّ على جلسة جماعية بلا مقاعد: `NULL or FALSE` يساوي `NULL`، و`check` يعتبر `NULL`
نجاحًا. الصيغة الصحيحة بـ`case` تُعيد `true/false` دائمًا. كشف هذا الاختبار وحده.

**٢. القيد المؤجَّل لا يصلح هنا.** `deferrable initially deferred` يفحص الرصيد عند
الـcommit — بعد أن يكون الـAPI قد ردّ على المستخدم. جُعل فوريًا ليصل الرفض في حينه.
